# Native Cycles volume Emission

## Cause and exact mapping

The additional Barbershop scene exposed `psycles.volume.emission` as the first
unsupported family in the native table builder. This is a contract socket-type
view of Cycles' existing EmissionNode, not a new SVM node. Projection now restores
that node, its Emission output, and its two domain mix weights.

The first complete external word comparison then exposed a second difference:
the importer inserted a transparent BSDF at an unconnected Surface output of a
volume-only material. Cycles leaves that output unconnected and records
`SD_HAS_ONLY_VOLUME`; the surface and shadow consumers handle the boundary.
The importer now uses its existing null-closure representation. Authored surface
closures are not removed. The separate legacy empty-material fallback is not
changed by this checkpoint.

The device interpreter also rejected volume Emission. Cycles' handler instead
multiplies the closure weight by `object_volume_density`, then uses the same
emission accumulator as surface evaluation. The production KernelGlobals adapter
now reads that exact KernelObject member, with density one for OBJECT_NONE.
The host/JIT optional reader fails closed for other objects when no table service
is supplied; it does not guess an object density. Cycles uses density one for
ordinary mesh geometry, including meshes with volume materials. Scale correction
belongs only to Volume geometry with object-space density, not every volume
boundary mesh.

No opcode, stack, PC, feature-mask, initialization, or coroutine policy is changed.
The mix-weight-zero early return and emission flag/set/accumulate behavior remain
Cycles' operations, including zero dynamic strength setting SD_EMISSION.

## Validation and remaining scene work

The full-scene canary exposed a third dependency: without the invented BSDF,
the path pipeline tried to sample an empty surface closure set and produced a
black image. Cycles instead bypasses shader evaluation, NEE, and BSDF sampling
at SD_HAS_ONLY_VOLUME. The native pipeline now implements that branch before
surface shading. It applies integrate_surface_terminate, increments only the
volume-boundary counter (limit 1024), advances RNG by PRNG_BOUNCE_NUM, changes
only ray tmin, and crosses the volume stack. Transparent/surface bounce counters,
path visibility, ray origin/direction/self IDs, MIS state, and differentials do
not change. This is an integrator correction, not another synthetic closure.

`cycles_volume_boundary_oracle.hip` invokes original Cycles
integrate_surface_terminate / integrate_surface_volume_only_bounce on its real
HIP SoA, covering 36 boundary-limit/probability/termination/tmin cases. The new
helper regression checks exact integer/tmin outputs and allows 1 ULP for
throughput division. The fallback native reciprocal produces 0x3f7fffff for
0.25/0.25 versus HIP's 0x3f800000; no compiler or slower arithmetic change is
introduced for that permitted difference. The full renderer regression
uses the original exported 2320 geometry bytes (text-encoded) and scene, renders
8x8/16 samples through both megakernel and staged coroutine modes, checks the
entire film for finite values, and compares eight interior/corner pixels with
the original Cycles HIP EXR. Those pixels exclude stochastic edge coverage.
The geometry SHA-256 is
`44518ec01466447e6e192e52879ccfda03ece613efead04e7516f03006fab858`.
The external 8x8 film SHA-256 is
`ff08f1f84ae81eefa1cc3b7d248cb0e33286634e7a3d442a21a6bea6fbcacab9`.
