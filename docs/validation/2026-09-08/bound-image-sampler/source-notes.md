# Bound image sampler: semantic and measurement contract

## Original contract and structural discrepancy

Authority: Cycles 5.2.1 source at
/home/mike/Projects/blender-cycles-trace-5.2, revision
cb168525138fecc792cc393f94afc39582b0103c. The retained light.cpp/svm.cpp
diagnostic edits do not change the image functions used by this oracle.

Original kernel/device/gpu/image.h resolves an ImageManager handle to
KernelImageInfo. Its texture object carries filter/address state. For
full-image float/byte RGBA data, ordinary interpolation uses one native
sample; CUBIC/SMART use four bilinear samples. device/hip/device_impl.cpp
710–735 maps REPEAT/EXTEND/CLIP/MIRROR to wrap/clamp/border/mirror and
CLOSEST to point, all other admitted interpolation to bilinear. The CUDA
device constructor has the same contract.

Psycles' prior runtime adapter instead recorded a 3 x 4 product of sampler
choices, cloning 4 * (1 + 1 + 4) = 24 native sample call sites. Each path
executed only its selected branch; 24 call sites does not mean 24 texture
fetches per path. The structural correction puts sampler choice in the
bound descriptor and records only ordinary-versus-bicubic algebra (5 sites).
No scene-name optimization or profile-derived allocation is involved.

Each native handle owns a distinct descriptor above the retained legacy
resource-slot range. Descriptors may share one decoded/uploaded image.
Generated sky slots and all later allocations respect the resulting maximum.
Failed-image bindings retain their identity/early return without allocating
or touching a texture. The 8-byte binding and SVM words, PC, offsets, feature
masks, closure state, sampler dimensions and row-orientation adapter are
unchanged. The bicubic polynomial is a mechanical extraction shared with
the explicit-sampler helper; no inlining policy or arithmetic path changes.

## Regression boundaries

- The XIR shape regression failed on unmodified production code: 24 native
  sample sites versus the original contract's 5. Raw evidence is
  bound-sampler-red-build.log / bound-sampler-red-hip.log below.
- Existing mode/projection/derivative tests retain their explicit native
  sampler control. All 16 interpolation/extension combinations have separate
  descriptors over the same image. Missing-image and Nishita fixtures now
  bind their actual CLIP/EXTEND samplers, rather than relying on an override.
- test_luisa_cycles_svm_image_binding.cpp uses the complete scene compiler
  and uploader, not manually assembled production descriptors. Sixteen
  ImageManager handles retain distinct metadata while images.size() remains
  two: one dummy plus one actual image. Eighty sample cases produce 320
  native-control comparisons on every tested backend.
- tools/cycles_svm_image_binding_oracle.hip directly invokes the original
  Cycles GPU svm_image_texture. It creates the same normalized BYTE4 texture
  object and reports 80 RGBA results. On HIP, another 320 assertions compare
  the complete scene-upload path with those original GPU outputs. Fallback
  and Vulkan retain the native-control assertions; this is not a claim that
  their filtering precision is numerically identical to Cycles HIP.

The original GPU fixture checks the sampler-binding boundary at identical
physical storage coordinates. It includes the existing top-down UV mapping
in its input preparation, not a substitute image evaluator. Whole-scene
references retain original Cycles coordinates and rendering, and therefore
remain necessary to validate the complete orientation adapter.

An earlier unadapted-coordinate probe found case 53 / red = 0.102166079 in
Cycles versus approximately 0.101767 in both new binding and old explicit
native-control paths. This occurs at an out-of-image cubic/CLIP sample under
the row-direction reversal. The raw canonical-coordinate probes are retained;
no renderer arithmetic, interpolation or tolerance was changed to force
bitwise agreement. Do not relabel the storage-coordinate fixture as full
image-orientation or cross-backend filtering parity.

The first integration-test build needed an explicit OutputRef; its first
scene also omitted required Image Texture properties. The original HIP host
wrapper initially needed an explicit texture-object pointer-to-uint64 cast.
These test/harness setup errors are not the structural red regression.
