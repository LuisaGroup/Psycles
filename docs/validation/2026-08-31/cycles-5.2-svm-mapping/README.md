# Cycles 5.2 SVM Mapping / TextureMapping validation

Date: 2026-08-31

## Scope

This milestone copies the Mapping and texture-node `TextureMapping` model from
Blender Cycles 5.2.1 into the Luisa SVM path. It does not claim complete shader
graph or scene parity; those require the remaining SVM node families.

## Structural correspondence

Cycles has two distinct host entities with distinct device encodings:

| Source entity | Host representation | Device stream |
| --- | --- | --- |
| authored ShaderNodeMapping | `MappingNode` | `NODE_MAPPING` |
| mapping embedded in a TextureNode | `TextureMapping` member | `NODE_TEXTURE_MAPPING`, optional `NODE_MIN_MAX`, optional NORMAL normalize |

The Blender serialization boundary temporarily represents embedded texture
mapping as a synthetic Mapping node. Projection recognizes only the explicit
`LegacyTextureMapping` marker, requires exactly one `TextureNode.Vector`
consumer, copies the state into that texture node, and contracts the synthetic
edge. An authored Mapping node has the marker set to false and is never
contracted.

Formally, for a marked node `m` and texture node `t`, projection is defined only
when `outdegree(m.Vector) = 1` and that edge terminates at `t.Vector`. Replacing
`p -> m -> t` with `p -> t` while transferring the complete mapping state to
`t` preserves the unique value dependency and the emitted evaluation order.
Any violation is rejected rather than guessed. This is why a generic Mapping
node cannot accidentally become texture state and why one embedded transform
cannot be duplicated across multiple consumers.

For a non-identity embedded mapping, compilation allocates a temporary SVM
stack region, emits the mapping into that region, emits the texture operation
that consumes it, and releases the temporary immediately afterward. Identity
mapping reuses the source offset. The temporary therefore spans exactly one
producer-consumer interval and cannot alias a live texture input.

Device evaluation follows the Cycles type model:

- POINT applies scale, rotation, and translation; derivatives use the linear
  direction transform.
- TEXTURE applies inverse translation/rotation/scale; derivatives exclude the
  translation term.
- VECTOR applies scale and rotation only.
- NORMAL applies inverse scale and rotation followed by dual normalization.
- embedded transforms apply the affine transform to values and its linear part
  to derivatives.
- `NODE_MIN_MAX` clamps only value lanes, preserving derivative lanes exactly
  as the Cycles stack implementation does.

The common immediate-or-stack decoding for `dual1` and `dual3` now lives in the
SVM stack layer, mirroring Cycles' typed `stack_load<dual*>` specialization and
preventing per-node reinterpretations of the bytecode ABI.

## External Cycles oracle

The oracle was generated by the diagnostic Cycles build. Its patch only dumps
the already-compiled SVM stream; the compiler and kernels remain those of the
pinned Cycles source.

```sh
/home/mike/Projects/blender-install-5.2-hiprt/blender \
  --background --factory-startup \
  --python tools/create_cycles_shader_probe.py -- \
  /tmp/psycles-svm-mapping.givshw/image_texture_node_mapping.blend \
  image_texture_node_mapping

PSYCLES_CYCLES_SVM_DUMP=/tmp/psycles-svm-mapping.givshw/image_texture_node_mapping.svm52 \
  /home/mike/Projects/blender-install-psycles-trace-5.2/blender \
  /tmp/psycles-svm-mapping.givshw/image_texture_node_mapping.blend \
  --background --python tools/render_cycles_golden.py -- \
  /tmp/psycles-svm-mapping.givshw/image_texture_node_mapping.exr \
  16 4 1 0 --cycles-device CPU
```

Artifact hashes:

```text
blend  7fabe6c778dd927c8261a80397cffd222aa06bc9e1957d76dde84f750d625661
```

The permanent host regression compares every shader-local word for POINT,
TEXTURE, VECTOR, and NORMAL embedded mapping against this external stream. It
also proves that authored Mapping retains `NODE_MAPPING`, exercises Cycles'
constant-fold rules, and rejects a marked mapping with a non-texture consumer.

## Validation

Build:

```sh
cmake --build build --parallel 32
```

Focused backend canary:

```sh
build/bin/psycles_luisa_cycles_svm_mapping_tests hip
build/bin/psycles_luisa_cycles_svm_mapping_tests fallback
LUISA_VULKAN_USE_XIR=1 \
LUISA_VULKAN_REQUIRE_NATIVE_XIR_SPIRV=1 \
LUISA_VULKAN_DISABLE_DXC=1 \
  build/bin/psycles_luisa_cycles_svm_mapping_tests vk
```

Full suites:

```sh
ctest --test-dir build --output-on-failure -j32 \
  -E '(_fallback|_vk|_hip)$'
ctest --test-dir build --output-on-failure -R '_hip$' -j1
ctest --test-dir build --output-on-failure -R '_fallback$' -j1
LUISA_VULKAN_USE_XIR=1 \
LUISA_VULKAN_REQUIRE_NATIVE_XIR_SPIRV=1 \
LUISA_VULKAN_DISABLE_DXC=1 \
  ctest --test-dir build --output-on-failure -R '_vk$' -j1
```

Results:

- non-backend: 85/85 passed
- HIP: 93/93 passed
- fallback: 95/95 passed
- strict native XIR to SPIR-V Vulkan, DXC disabled: 93/93 passed

The device regression covers ordinary and derivative evaluation, exact cursor
advance for each payload, all four Mapping modes, a transform copied word for
word from the external Cycles stream, Min/Max behavior, and NORMAL dual
normalization. This micro-probe has no meaningful scene image to compare, so no
visual-parity or full-scene performance conclusion is drawn from it.
